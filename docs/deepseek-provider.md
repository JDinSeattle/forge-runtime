# DeepSeek Responses adapter and evaluation registration

Implementation and offline protocol evidence only. No credential file was created, provider endpoint called, service deployed, or evaluation run started. The authorized evaluation ceiling is $2; the four fixed eval-v2 tasks each have a $0.50 allocation. The memory-only credential sentinels in unit tests reach only an in-process RoundTripper.

## Official protocol checked on 2026-09-12 UTC

The current pricing page routes the accepted request alias `deepseek-v4-flash` to DeepSeek-V4.1-Flash. This is not a pinned 0731 model. The adapter preserves the requested alias in the persisted request and the returned `model` in `ModelTurn.provider_model` and the original protected native response. The latter is a server assertion; a missing/alias-only version cannot prove an immutable model build. [Official pricing](https://api-docs.deepseek.com/quick_start/pricing/)

The native endpoint is `https://api.deepseek.com/responses`. Its streaming completion, stateless input replay and inclusive cached-input usage follow the official Responses guide. `previous_response_id`, server-side storage and built-in tools are not used. The code requires a single initial creation event, increasing sequence numbers, a completed final response, matching final tool arguments and text, noncontradictory output-item status, then clean stream completion. `incomplete`, `failed`, malformed input, unknown native tools, body/argument limits or transport errors return no executable calls. [Responses guide](https://api-docs.deepseek.com/guides/responses_api/)

The initial request explicitly sets `reasoning.effort=none`. This keeps the existing closed-batch portable context compaction valid without claiming to preserve an entire thinking history. Plaintext native reasoning/unknown response fields, if returned, stay in the protected continuation artifact and are not emitted as public model deltas. Only registered function tools are enabled; JSON schema validation and application command approval remain mandatory. This does not implement custom `apply_patch`, vision, JSON-output mode, native compaction, search or async tools. [Thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/), [tool calls](https://api-docs.deepseek.com/guides/tool_calls/)

The source field snapshot and observation bounds are in [sources/deepseek-20260912.json](sources/deepseek-20260912.json). It is a documentation observation, not real endpoint verification. A later Responses-page re-fetch timed out; the successful earlier guide read remains the protocol source.

## Identity, accounting and budget

`configuration.BuildProviders` accepts `deepseek` only with `DEEPSEEK_API_KEY`. The adapter constructs the SDK's standalone `ResponseService`, which does not read OpenAI client environment defaults. `OPENAI_API_KEY`, base URL, organization, project and custom headers cannot silently configure this client. The production endpoint is fixed and HTTP redirects are refused. DeepSeek model registrations cannot share a credential-group quota with another provider in the loaded configuration. Native state cannot cross provider identities. SDK retries are disabled; attempt IDs correlate requests and the existing application owns persisted attempts, retry policy, approval and quota reservations. Correlation is not a vendor-side exactly-once guarantee.

The proposed peak ceiling is 300,000 input / 1,200,000 output / 6,000 cached-input **micro-USD per million tokens**. `exact_pricing=false` is intentional because a local request clock does not prove the applicable billing period. For 32,768 input plus 8,192 output tokens, the rounded request reservation is **19,661 micro-USD**. Twenty such reservations are 393,220 micro-USD per task, within 500,000. A retry also reserves capacity; the run and batch caps still apply. None of these values verifies an invoice. [Official pricing](https://api-docs.deepseek.com/quick_start/pricing/)

For an applicable exact operator quote, input includes cached tokens, so only `input-cache_read` gets the uncached rate. Output already includes reasoning tokens and is not charged twice. Missing input/output/cache counters remain unknown; interrupted terminal counters are lower-bound observations with `Final=false`. A peak-only quote remains unknown even after a complete response, retaining its reservation through the existing ledger path. Request-slot deadline release is separate from releasing unknown monetary exposure. [Responses usage](https://api-docs.deepseek.com/guides/responses_api/), [token usage](https://api-docs.deepseek.com/quick_start/token_usage/)

`evaluation.prepare` preserves the independent provider/model/credential group, source URLs, explicit $2 total and four task allocations. It writes candidate configuration only. Existing collection downloads checksum-verified `model_response` artifacts, which retain `provider_model` and native response fields; the aggregate `model_id` remains the requested alias. Existing deployment and paid-execution gates in [evaluation.md](evaluation.md) still apply.

## Offline verification and limits

New tests use native SSE bodies through an in-process HTTP transport, with no socket or remote call. They cover parallel tool fragments and native continuation, provider credential isolation, missing/reordered sequences, final identity/text/argument disagreement, incomplete or absent usage, unsupported tools, no hidden HTTP retries, deadlines, consumer rejection and byte limits. Pricing tests check inclusive cache arithmetic, unknown quote/counter handling and the exact 19,661-micro-USD reservation. Python tests validate candidate-only DeepSeek registration, retained identity and the four-task budget sum. A new in-memory test runs the unchanged original OpenAI wire fixture and checks its encrypted continuation request parameters.

The initial offline run failed one test because its 160-byte argument limit exceeded the fixture size and therefore did not trigger rejection. The test now uses an actually restrictive bound. That failed log is retained separately; no production behavior was weakened to make it pass. A later transient compile failure while adding the created-response guard is also retained. Independent review identified contradictory completed-response item statuses; DeepSeek now rejects every supplied status except `completed`, while the old OpenAI fixture behavior is unchanged.

No DeepSeek live API, real vendor invoice, model quality, actual native-provider PostgreSQL integration or deployed credentials have been verified here. Previous OpenAI/Anthropic PG interruption and fallback evidence retain their original scope and are not DeepSeek evidence. The schema, runner, application approval protocol and lifecycle binaries are unchanged by this work.
