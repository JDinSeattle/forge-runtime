## P04: independent calculation from E25 F02

Sources are the original [acceptance record](../../benchmarks/results/application-continuation-20260911T200939Z/F02/acceptance.json), [pre-death PG capture](../../benchmarks/results/application-continuation-20260911T200939Z/F02/before-worker-death-postgres.json), [worker 2 ready marker](../../benchmarks/results/application-continuation-20260911T200939Z/F02/worker2-ready.json), [replacement PG capture](../../benchmarks/results/application-continuation-20260911T200939Z/F02/after-worker2-claim-postgres.json) and [completed PG capture](../../benchmarks/results/application-continuation-20260911T200939Z/F02/completed-postgres.json). The earlier independent audit already binds the run/tenant, original operation, snapshots and artifact bytes. This review recomputes timing from those same saved records; it is not a new execution.

The original run has no effects, model attempts, quota reservations, approvals or artifacts before death. The fixture's explicitly recorded SQLite checks find no workspace, operation or volume lease. The original lease is `20:09:40.942514Z` → `20:09:45.942514Z`, exactly **5 seconds**, and is not rewritten. Times below are UTC on 2026-09-11.

| Boundary | Timestamp / calculated interval |
| --- | --- |
| SIGKILL requested | `20:09:40.979436726` |
| Worker 2 ready | `20:09:41.052141333`; **72.704607 ms** after the signal request, before lease expiry |
| Natural lease expiry | `20:09:45.942514` |
| Replacement claim input, epoch 2 | `20:09:46.002725`; **60.211 ms** after expiry |
| Replacement `run.claimed` event row | `20:09:46.009202`; **66.688 ms** after expiry |
| First `workspace_ready` transition input | `20:09:46.776210`; **773.485 ms** after claim input, **833.696 ms** after expiry |
| Durable-history `workspace.prepared` event row | `20:09:46.777136`; **834.622 ms** after expiry; **5.797699274 s** after the signal request |

The production worker polls at 150 ms. The observed expiry→claim interval is below one scan interval; process startup has already completed before expiry. The first workspace progress follows its claim by 773.485 ms, covering local workspace/initial-verification startup. Signal request→workspace event is below **5 s lease + 150 ms scan + measured 773.485 ms startup = 5.923485 s**. The original task subsequently reaches verified completion. The timings come from one host's wall clock and persisted DB/event inputs; the signal marker is not a kernel death timestamp, and an event row timestamp is not a separately measured transaction-commit acknowledgement. Full task duration is deliberately excluded from recovery-only timing.
