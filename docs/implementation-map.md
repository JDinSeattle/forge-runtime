## Integration invariants and remaining risks

1. Do not conflate operation intent, durable acceptance and final receipt. A single boolean `success` cannot represent the RPC timeout gap.
2. Keep run version, lease epoch and workspace revision typed and separate. Adoption blocks new old-epoch starts before waiting for the old writer to stop.
3. Define canonical argument hashing once across worker, approval and runner; include operation identity/bindings when checking duplicates. Hash equality alone does not establish tenant ownership.
4. Define cancellation transition precedence while preserving actual completed effects. A cancel request never establishes executor termination by itself.
5. Define a trusted verification result independently of `completed`; ordinary regression success cannot become proof that the requested task was fixed.
6. Allocate tenant-scoped foreign keys from the start. Retrofitting ownership after globally keyed tables would leave subtle cross-tenant reference paths.
7. Keep quota reservations separate from scheduling/runner allocations; unknown model usage survives worker lease expiry.
8. Keep run snapshot state+event high-water mark transactional. A reconstructed CLI view must not skip commits made during reconnection.
9. Real rootless Docker availability and enforced cgroups must be checked early. A permissive host fallback cannot satisfy E.
10. Validate the current supported Go/generator/SDK versions in the actual environment; the parent document's version research is not executable compatibility proof.
